`evalmode` is a debug-only Kotlin port of the Python eval harness that runs golden cases against the *literal* production AI path, in-process, on the device — no HTTP round-trip, no mocks by default. It lives entirely under `app/app/src/debug/`, so it never compiles into a release APK, and it is reached from Dev Mode.

## Why it exists

The Python harness (`evals/`) grades the AI by calling a system-under-test over a frozen JSON contract. `evalmode` is the on-device incarnation of the `InProcessSimulator` that `evals/core/system.py` anticipated: it resolves the same `ContextCardRepository` the KB-chat ViewModel uses and calls `ask(...)` directly, so the agent loop, the real tool executor reading real Room, the live `ai-engine`, and the signed-in identity all execute for real. Every core type — `Case`, `Verdict`, `Judge`, `SystemUnderTest`, the chain primitives — is a faithful port of its `evals/` counterpart, so an on-device run and a Python run of the same case are directly diffable.

## The pipeline

`Runner` (`evalmode/core/Runner.kt`) drives every case through five stages:

| Stage | Owner | What happens |
| --- | --- | --- |
| Access | `EvalAccess` (`evalmode/access/EvalAccess.kt`) | Fail-closed gate — dev + Clerk test account or the run never starts. |
| Corpus | `CorpusStrategy` (`evalmode/core/CorpusStrategy.kt`) | Seed a case's declared fixtures into Room (or `Skip`). |
| Call | `SystemUnderTest` (`evalmode/core/SystemUnderTest.kt`) | Run the real production `ask()` path; capture the loop trace. |
| Judge | `Judge` (`evalmode/core/Judge.kt`) | Resolve the case's judge chain and grade the `ActualOutput`. |
| Record | `ResultWriter` (`evalmode/results/ResultWriter.kt`) | Persist per-run JSON to the device. |

## Composition root

`EvalComponent` (`evalmode/EvalComponent.kt`) is the debug-only composition root. It resolves the handful of app-level singletons it needs from the global Koin instance and constructs the eval graph directly — there is **no** debug Koin module and **no** `App.kt` change; everything stays in `src/debug`. It wires `EvalAccess`, `OnDeviceSystemUnderTest`, a `SeededCorpus` (which no-ops for cases without fixtures, so seeded and non-seeded suites share one run), `CaseLoader`, `SuiteRegistry`, and `ResultWriter` into a single `EvalViewModel`.

## Configuration

`EvalConfig` (`evalmode/EvalConfig.kt`) holds the debug-only constants, mirroring `evals/config.py`:

| Constant | Value | Purpose |
| --- | --- | --- |
| `MAX_CONCURRENCY` | `4` | Bounded parallelism (per the eval-workers guidance). |
| `PRODUCTION_MODEL` | `claude-haiku-4-5-20251001` | The model the on-device SUT prices agent spend against. |
| `JUDGE_MODEL` | `claude-sonnet-4-6` | First-tier LLM-as-judge model. |
| `ARBITER_MODEL` | `claude-opus-4-6` | Escalation arbiter below the confidence threshold. |
| `DEFAULT_CONFIDENCE_THRESHOLD` | `0.85` | Below this, a `MinConfidence`-wrapped PASS/FAIL demotes to UNCERTAIN. |
| `DEFAULT_PASS_FLOOR` | `0.95` | Minimum pass rate for a run to count as a passing build. |
| `ASSETS_ROOT` | `evals` | Bundled-asset root for cases/rubrics/fixtures. |
| `RESULTS_DIR` | `evals/results` | Device subdir under `getExternalFilesDir` for per-run JSON. |

`MODEL_PRICING` is a `Map<String, Pair<Double, Double>>` of worst-case PAYG rates (input, output per 1M tokens) covering the Claude models plus the Gemini family, so cross-family external judges price correctly. `modelCostUsd(model, in, out)` returns `0.0` for an unknown model rather than crashing. Two values are sourced from debug-only `BuildConfig` fields the Gradle build reads from `.env.local`: `judgeAnthropicKey` (`EVAL_JUDGE_ANTHROPIC_KEY` — blank ⇒ LLM judges SKIP cleanly) and `uploadUrl` (`EVAL_UPLOAD_URL` — blank ⇒ the Upload-to-PC button is hidden).

## Entry point

Dev Mode's `DevModeScreen` exposes an `onNavigateToEvalMode` button; `DebugNavGraph.kt` registers `composable<EvalMode>` → `EvalDashboardScreen`, whose top bar reads "AI Evals". The route type `EvalMode` comes from `ui.v1.navigation`. Because the whole package is in `src/debug`, the route and screen simply do not exist in a release build.
