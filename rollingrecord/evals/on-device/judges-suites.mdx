Grading is split between a per-case resolver and a library of composable judges. `SuiteRegistry` (`evalmode/suites/SuiteRegistry.kt`) is the Kotlin analog of every `evals/suites/<name>/judges.py`'s `judge_for_case`; the judges themselves are faithful ports of the `evals/judges/` families. Every type here — `Judge`, `JudgeContext`, `Verdict` — mirrors its `evals/core/` counterpart so on-device and Python verdicts line up.

## Judge and Verdict

A `Judge` (`evalmode/core/Judge.kt`) takes a `JudgeContext` (the `case`, the `ActualOutput`, and the shared `CostLedger`) and returns one `Verdict`. The contract: never throw on normal disagreement — return `UNCERTAIN` for ambiguity, `SKIP` for inapplicability; throw only on infrastructure failure. `evaluate` is `suspend` because LLM-as-judge implementations make a network call.

`Verdict` (`evalmode/core/Verdict.kt`) has a `VerdictKind` — `PASS`, `FAIL`, `UNCERTAIN`, or `SKIP` — plus `confidence`, `reason`, `judgeName`, `costUsd`, and optional structured `details`. The four kinds make the cascade rule unambiguous: `PASS`/`FAIL` are terminal (`isTerminal`); `UNCERTAIN` ("ran but unsure") and `SKIP` ("couldn't meaningfully run") both advance a cascade. Factory helpers `Verdict.passed/failed/uncertain/skipped` construct them.

## Chain primitives

The composable aggregators in `evalmode/judges/Chains.kt` are themselves `Judge`s, so they nest into arbitrary trees. A `SKIP` advances a `Cascade` without contributing and is treated as non-participation by the others; if every child SKIPs, the chain returns `SKIP`. Cost is the sum of every child that ran.

| Primitive | Rule |
| --- | --- |
| `Cascade(…)` | Try judges in order; the first `PASS` or `FAIL` halts, `UNCERTAIN` advances. Cheap judges first, LLM judges last. |
| `AllOf(…)` | Every non-SKIP child must PASS. Any FAIL → FAIL; else any UNCERTAIN → UNCERTAIN; else PASS. |
| `AnyOf(…)` | Any PASS → PASS; unanimously FAIL → FAIL; otherwise UNCERTAIN. |
| `Majority(judges, n)` | At least `n` of the judges must PASS (UNCERTAIN/SKIP count as not-PASS). |
| `MinConfidence(judge, t)` | Rewrite a PASS/FAIL whose confidence `< t` as UNCERTAIN, so a `Cascade` escalates. SKIP/UNCERTAIN pass through. |

## The standard fan-out

Most suites use one shape: an `AllOf(structural judges…)` combined with the LLM tier unless the case opts out via `expected.judge_chain`. The LLM tier is `llmCascade()`:

```
Cascade(MinConfidence(LlmJudge(Sonnet), 0.85), LlmJudge(Opus))
```

Sonnet grades first; if its confidence falls below `DEFAULT_CONFIDENCE_THRESHOLD` (0.85), `MinConfidence` demotes it to UNCERTAIN and the Opus arbiter (`ARBITER_MODEL`) decides. The LLM tier is always appended and self-SKIPs when `llm_rubric` is absent or the judge key is unset — matching Python's "degrade to structural-only when Anthropic/rubric is unavailable" without a separate branch.

## Per-case resolution

`judgeFor(case)` (fed to `Runner.judgeProvider`) picks the chain per case from `case.suite`, its `tags`, and `expected.judge_chain` — exactly like Python. An unknown suite returns `null`, which the runner records as UNCERTAIN so the pipeline still runs. All 15 suites are wired:

| Suite | Chain |
| --- | --- |
| `kb_chat` | Per-tag: capability listing, factual recall, or free-text quality; else `KeywordsJudge`. |
| `abstention` | Standard fan-out + `FaithfulnessJudge`. |
| `context_architecture` | Standard fan-out (with `ToolCallSequenceJudge`) + `FaithfulnessJudge`. |
| `efficiency` | `WasteThresholdJudge` + budget/tool judges; opt-out `waste_only`. |
| `extract_template` | `ToolCallJudge` spine + LLM cascade + `GroundedExtractionJudge`. |
| `kb_chat_session` | Standard session fan-out + `ContainsJudge`. |
| `kb_chat_session_live` | Standard session fan-out. |
| `long_recording` | Standard session fan-out + `ContainsJudge`. |
| `multi_recording` | Standard session fan-out + `ContainsJudge`. |
| `rag_real_content` | Session fan-out + `RetrievalRecallAtK` / `PrecisionAtK` / `MRR`. |
| `response_variety` | Budget + must/must-not-call tool judges. |
| `source_attribution` | Same session fan-out as `multi_recording` (`MustNotCallToolJudge` load-bearing). |
| `security` | `deterministic_only` gate, bare LLM cascade for security-tagged cases, else `KeywordsJudge`. |
| `template_moderation` | `BodyFieldJudge` (single-shot structured op). |
| `tool_correctness` | Standard session fan-out + `ContainsJudge`. |

The `kb_chat` resolver branches on `capability` / `factual_recall` / `hallucination`/`refusal`/`multi_turn`/`quality` tags; the `security` resolver treats a set of injection/leakage/privacy tags (`SECURITY_TAGS`, e.g. `prompt_injection`, `system_prompt_leak`, `data_exfiltration`) as security cases. Both honor a `deterministic_only` / `with_llm` override in `expected.judge_chain`.

## Deterministic judges

Pure code, zero LLM cost (`evalmode/judges/Deterministic.kt`). Each reads its own `expected.*` keys and SKIPs when they're absent, so many judges share one `expected` object:

| Judge | Keys | Checks |
| --- | --- | --- |
| `ExactMatchJudge` | `exact` | Exact string equality with the actual text. |
| `ContainsJudge` | `must_contain`, `must_not_contain` | Required substrings present, forbidden ones absent. |
| `KeywordsJudge` | `must_contain_keywords`, `min_keyword_hits` | At least N of the keywords appear. |
| `RegexJudge` | `regex_must_match`, `regex_must_not_match` | Regex presence/absence. |
| `LengthJudge` | `min_length`, `max_length` | Text length within bounds. |
| `ListShapeJudge` | `must_be_list_shape`, `min_list_items` | Answer is a list of ≥ N items (bullets/numbers/commas). |
| `BodyFieldJudge` | `body_fields` | Scalar body fields equal (or one-of a list). |
| `ToolCallJudge` | `tool_calls` | Total/per-tool call-count bounds; `saveSection` title keywords. |

`evalmode/judges/Fuzzy.kt` adds `LevenshteinJudge` (`fuzzy_target`, `fuzzy_threshold` default 0.85) and `SetSimilarityJudge` (`set_similarity_target`, threshold 0.6, Jaccard over word tokens). The shared JSON accessors (`str`, `int`, `bool`, `strList`, `obj`, `arr`, `actualText`) live in `evalmode/core/JsonAccess.kt`.

## Session-structural judges

Pure judges that read the reconstructed `body._session` block (`evalmode/judges/SessionJudges.kt`). When that block is absent — a single-shot, non-session case — each SKIPs:

| Judge | Key | Checks |
| --- | --- | --- |
| `MustCallToolJudge` | `must_call_tools` (`list[str]` or `{names, any_of}`) | Required tools were called (all, or any-of). |
| `MustNotCallToolJudge` | `must_not_call_tools` | Forbidden tools were never called. |
| `RoundBudgetJudge` | `round_budget` (`{min, max, allowed_terminals}`) | Round count in range and terminal reason allowed. |
| `ToolCallSequenceJudge` | `tool_call_sequence` | Named tools appear in order (subsequence match). |
| `WasteThresholdJudge` | `waste_threshold` | Round count at or below the waste ceiling. |

`RoundBudgetJudge`'s default allowed terminals are `end_turn`, `scripted_end`, and `max_rounds_exceeded`.

## Retrieval-quality judges

`evalmode/judges/Retrieval.kt` (RR-378/379) scores which transcript chunks the loop retrieved against a gold set. All three read `expected.gold_chunk_ids` (SKIP if missing) and parse retrieved chunk IDs from `_session.all_tool_results[].result` via the `=== chunk <id>` header the production snippet tools emit:

- `RetrievalRecallAtK` — `retrieval_recall_at_k` (`{k, threshold}`, defaults k=5, threshold=1.0).
- `RetrievalPrecisionAtK` — `retrieval_precision_at_k` (threshold 0.0 = informational).
- `RetrievalMRR` — `retrieval_mrr` (mean reciprocal rank of the first gold chunk).

## LLM-backed judges

These call Anthropic directly and record their spend on the ledger.

- `LlmJudge` (`evalmode/judges/Llm.kt`) reads `expected.llm_rubric` (SKIP if absent), renders the actual output, and asks the judge model for `{verdict, confidence, reason}` JSON. For a multi-round session it renders the full round-by-round transcript, marking which rounds were user-visible (`end_turn`) versus internal scratch — because Supabase Edge Functions don't stream, only final-answer rounds reach the user, and the judge is told to grade user-visible prose only from those. A shared `extractJsonObjectText` salvages the object from fenced/prose responses.
- `FaithfulnessJudge` (`evalmode/judges/Faithfulness.kt`) decomposes the answer into atomic claims and checks each against `expected.faithfulness_source` (threshold default 0.8). An answer with no claims — a correct abstention — passes; a JSON-parse failure is UNCERTAIN, not FAIL.
- `GroundedExtractionJudge` (`evalmode/judges/GroundedExtraction.kt`) pulls extracted text from `saveSection`/`replaceSection`/`saveTasks` tool calls and checks each field is grounded in `case.input.input.transcript` (threshold `grounding_threshold`, default 0.8); SKIP without a transcript or extraction calls.
- `EmbeddingSimilarityJudge` (`evalmode/judges/Semantic.kt`) is a parity stub that always SKIPs, mirroring `evals/judges/semantic.py`, which never wired an embedding model into the judge.

## The Anthropic client

`AnthropicMessages` (`evalmode/Anthropic.kt`) is a minimal direct Messages API client for the judges — a faithful port of `evals/_anthropic.py` with no provider fallback, streaming, or tool use. The key is validated at *call* time, not construction, so the object graph builds with an unset key and `LlmJudge` catches the failure and SKIPs. `complete(...)` returns a `MessagesResult` with text and token usage.

## Loading cases

`CaseLoader` (`evalmode/data/CaseLoader.kt`) reads bundled case JSON from the debug APK's assets, mirroring the Python `load_suite_cases` layout: `assets/evals/suites/<suite>/{small,med,large}/`, each `.json` file a JSON array of `RawCase` objects. `TokenBucket` maps the `small`/`med`/`large` cost tiers (`< 500`, `500–5,000`, `5,000+` input tokens). `listSuites()` enumerates the suite directories; a duplicate case id within a suite throws, naming both source assets. Each `RawCase` is enriched by the loader into a frozen `Case` (`evalmode/core/Case.kt`) carrying the loader-set `suite` / `bucket` / `sourcePath`.
