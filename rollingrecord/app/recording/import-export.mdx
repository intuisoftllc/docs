title: "Importing & Exporting Recordings"

Audio can move in and out of RollingRecord five ways: opening a single audio file from another app for preview (deep link), importing shared files via the share sheet, sharing recordings out through the system share sheet, saving recordings to the device's Downloads folder, and bulk-importing or bulk-exporting all recordings as a zip archive.

## Opening a single audio file (deep link preview)

RollingRecord registers for `Intent.ACTION_VIEW` on audio MIME types. When another app opens an audio file with RollingRecord, `MainActivity.onCreate` (or `onNewIntent` if already running) captures the `Uri` and routes it into the V2 External Playback preview via a hoisted latch (`v2ExternalAudioUriPending`) that `V2App` / `V2MainNavHost` consume. The preview lets the user listen to the file and then choose to import it into the library.

## Sharing INTO the app (`ACTION_SEND` / `ACTION_SEND_MULTIPLE`)

The manifest declares a share-target alias, so RollingRecord appears in other apps' share sheets for `audio/*`. `MainActivity.handleShareIntent(intent)` is the only enforcement point for shares.

### Reading the payload

`sharedAudioUris(intent)` returns the URIs the sender attached:

- `ACTION_SEND` → the single `Intent.EXTRA_STREAM`.
- `ACTION_SEND_MULTIPLE` → the `EXTRA_STREAM` list.
- **`ClipData` fallback** — plenty of senders (including ShareCompat and anything built on the AndroidX sharing helpers) leave `EXTRA_STREAM` null and attach the payload as `ClipData`. Reading only `EXTRA_STREAM` used to resolve those shares to "no files" and drop them silently. The fallback iterates `clipData` items so those senders now work.

Uses the deprecated non-typed `getParcelableExtra` overloads on purpose: the typed API only exists on API 33\+ and `minSdk` here is 26.

### Admission gates

The alias is enabled for everyone (reinstalling wipes component-enabled state, so gating by disabling the component was unreliable and duplicated logic that had to live here anyway — the component is exported and can be invoked directly). Every share therefore re-derives admission:

- **Signed out** — refused synchronously. `sessionIdFlow` is seeded from SharedPreferences at process start, so this is authoritative immediately, unlike auth state which may still be restoring. Import writes to the active user session's directory and DB; with no session there is no correct destination.
- **Access unknown** — after a bounded `ACCESS_RESOLVE_TIMEOUT_MS` wait for `proAccessFlow` to settle to something other than `UNKNOWN`, an unresolved answer is treated as a refusal. Fail-closed matches `TileStartActivity`. `UNKNOWN` deliberately shows nothing — claiming they need to upgrade could be a lie.
- **Below Pro** — the app routes to the Upgrade screen via `v2ShareNeedsUpgradePending`, matching what ⋮ → Import does for the same capability.
- **Pro\+** — the share is accepted; import runs and the app lands on All Recordings via `v2AllRecordingsPending`.

The whole handler is `runCatching`-guarded because a share is reached from another app's UI. A crash here would read as "that app broke my phone" and the user would have no way to retry into a different code path.

## `RecordingImporter`

`RecordingImporter` (`service/RecordingImporter.kt`) is the session-scoped engine that copies external audio into the app and inserts `Recording` rows. It is deliberately NOT owned by a screen ViewModel: import must keep running (and its progress indicator must keep showing) even if the user leaves the All Recordings screen and comes back. Work runs on the importer's own `SupervisorJob + Dispatchers.IO` scope; the in-flight count is a `StateFlow` any screen can re-observe.

- **`importingCount: StateFlow<Int>`** — total files currently being copied across all in-flight batches. Drives the shimmer ghost cards at the top of the Manual list. Additive so a second batch started before the first finishes stacks.
- **`results: SharedFlow<ImportResult>`** — one-shot per-batch outcome with no replay. If no screen is listening, the newly-inserted cards are the feedback instead. `ImportResult` is now `data class ImportResult(succeeded, failed, unsupported = 0)`. `failed` and `unsupported` are **disjoint**: `unsupported` counts files refused because the format isn't usable (not audio, undecodable, or the transcoder rejected it), while `failed` is I/O / copy / unexpected errors. The split exists so the completion toast can say "that file type isn't supported" instead of a generic failure that reads as an app bug.
- **`close()`** (Closeable) — called automatically by Koin when the user-session scope closes. Cancels in-flight imports on sign-out so an import running during a sign-out cannot keep writing recording rows into the outgoing user's DB.
- **Not process-death survivable.** A mid-import app kill abandons in-flight copies. Acceptable; a WorkManager job would be needed for process-death survival and is out of scope.

Per-file flow (`import(uris)`):

1. Read `DISPLAY_NAME` from the ContentResolver. Fall back to `"Import ${index + 1}"`.
2. **Cap the derived name at 40 chars** (`IMPORT_NAME_MAX_CHARS`), matching `LibraryNameEntrySheet.maxLength`, so an imported file with a long filename cannot produce a recording name longer than the rename UI would allow the user to type.
3. **Resolve an admission extension** via `resolveExtension(uri, displayName)`: the filename extension wins when it names a format in `SUPPORTED_AUDIO_EXTENSIONS`; otherwise the declared MIME is mapped through `MIME_TO_EXTENSION` (`audio/mpeg`, `audio/mp4`, `audio/wav`, `audio/ogg`, `audio/opus`, `audio/flac`, `audio/3gpp`, `audio/amr`, and common variants). `application/octet-stream` stays absent — "some bytes" is not a claim of audio — but since RR-192 **any other** `audio/`-prefixed MIME is admitted too, resolving to the temporary extension `"bin"`. Only a genuinely unresolved extension is refused; it increments `unsupported` and skips.
4. **Copy under a temp name.** The URI is copied to `imported_${now}_${index}_src.$ext` in `filesDir/recordings/{user-segment}/` first. The final name, extension, and stored `format` column are decided **after** content-sniffing (and any transcode), so a lying extension cannot dictate what is stored.
5. **Probe duration and sample rate** via `MediaMetadataRetriever`. A null/0 duration on a non-trivial file (`> 1 KiB`) means the bytes are unplayable — delete the copy and count it `unsupported` (no longer `failed`).
6. **Classify to a pipeline-native shape** with `classifyNative(srcFile)`, which sniffs the first 12 bytes into one of three shapes: `RIFF`+`WAVE` → `.wav`, format `wav`; `OggS` with `AudioFileProbe.probe == "opus"` → `.ogg`, format `opus`; `ftyp` at offset 4 with probe `== "aac"` → `.m4a`, format `aac`. Native files are renamed to the canonical extension and kept as-is. Everything else (mp3, flac, amr, 3gp, Vorbis-in-OGG, raw ADTS `.aac`) is **transcoded** to AAC/M4A via `AudioSplicer.splice(srcFile, destFile, listOf(0L to durationMs))` — a full-range splice that reuses the trim pipeline — and stored as format `"aac"`. A file that cannot be transcoded, or has 0 duration, is deleted and counted `unsupported`. The old extension-keyed `format = when(ext){ "wav"->…, "mp3"->"mp3", "m4a"/"mp4"->"aac", … }` mapping is gone: the stored format is now always `wav` / `opus` / `aac`, derived from content, never the extension. `CancellationException` is rethrown at both the per-file catch and inside the transcode catch, because session teardown is not a per-file failure.
7. `RecordingRepository.insertRecording(Recording(..., mode = MANUAL, sessionId = null, createdAt = now + index, format = <derived>, ...))`. The `+ index` offset preserves ordering.
8. Decrement `importingCount` as each file resolves so the ghost cards shrink toward the real cards as they appear.

Admission extensions (`SUPPORTED_AUDIO_EXTENSIONS`): `mp3`, `aac`, `m4a`, `mp4`, `wav`, `ogg`, `oga`, `opus`, `flac`, `3gp`, `3gpp`, `amr`. This is the set the importer is willing to **try** — not a promise of end-to-end support. The content sniff and the transcoder are the real filter now.

The import transcode rides the reworked `AudioSplicer` (see [Trim](/rollingrecord/app/playback/trim)). Small-frame codecs like AMR-NB (20 ms / ~320-byte frames), which formerly took roughly a minute per 2-minute file, now finish in seconds: the MediaCodec loop uses opportunistic 0-timeout dequeues with adaptive waits instead of paying a fixed `TIMEOUT_US` on every dequeue, and the encoder end-of-stream is retried via an `encoderEosPending` flag so it can no longer be silently dropped (which previously hung the loop forever). WAV sources bypass MediaCodec entirely through the `spliceWav` byte-range fast path.

## Sharing recordings OUT

`ShareUtils.shareFiles(context, filePaths, chooserTitle)` (`util/ShareUtils.kt`) launches the native Android share sheet:

- One file → `Intent.ACTION_SEND` with `type = "audio/*"`.
- Multiple files → `Intent.ACTION_SEND_MULTIPLE`.

Paths are deduplicated by canonical path so sharing a session does not double-attach individual segments. Each path is wrapped as a content Uri via `FileProvider.getUriForFile(context, "${packageName}.provider", file)` with `FLAG_GRANT_READ_URI_PERMISSION` on the outgoing intent.

## Saving to Downloads

`ShareUtils.saveToDownloads(context, filePaths)` copies recordings directly into the device's Downloads folder:

- **API 29\+** — via `MediaStore.Downloads.EXTERNAL_CONTENT_URI` with `ContentValues` for filename and MIME type.
- **Older APIs** — writes into `Environment.getExternalStoragePublicDirectory(DIRECTORY_DOWNLOADS)`.

Returns the number of files successfully saved. Callers dispatch this off the main thread — file IO runs inline.

## Bulk export

`RecordingsZipExporter.export(context, destination, onProgress)` (`util/RecordingsZipExporter.kt`) walks `filesDir/recordings/` and writes every audio file (`.m4a`, `.aac`, `.wav`, `.mp3`, `.ogg`, `.opus`) into a single zip at a user-chosen destination Uri (typically picked through the Storage Access Framework's Create Document intent, landing in Downloads).

- **Never touches the database.** Designed to work even in the `FatalDbErrorScreen` recovery path when Room is unopenable. Per-user segments become top-level folders in the zip so a device with both signed-in and anonymous recordings still exports everything.
- **Manifest marker.** The first entry is `manifest.json` (`MANIFEST_FILENAME`) with `format = "rollingrecord_recordings_export"` (`MANIFEST_FORMAT`). `RecordingsZipImporter` rejects any zip that does not begin with a valid manifest, so hand-built zips of random audio cannot be imported by accident or on purpose.
- **Progress callback.** `onProgress(current, total)` fires after each entry completes so the UI can render a determinate progress bar.
- **Audio only.** No metadata, names, categories, or transcripts are exported. Re-import brings audio back as fresh `Recording` rows through the orphan-scanner path.

## Bulk import

`RecordingsZipImporter` (`util/RecordingsZipImporter.kt`) streams a zip Uri, extracts each audio entry into `filesDir/recordings/{relative-path-from-zip}/`, and reimports the new files via `OrphanedAudioScanner.importFiles`.

### Manifest and version gate

The importer reads the first entry and rejects the zip unless:

- The entry name is `manifest.json`.
- `format` is `"rollingrecord_recordings_export"`.
- `version` is within `MIN_SUPPORTED_MANIFEST_VERSION..MANIFEST_VERSION`.

Zips built by hand, or old exports whose format has been retired, or newer exports the current app cannot understand, are refused rather than silently doing the wrong thing.

### Dedup

Deduplication runs on both layers:

1. **True duplicate (disk \+ DB).** File exists on disk **and** its absolute path is already in the DB → skipped entirely. Neither the file nor the row is touched. Counted as `skippedFiles`.
2. **On disk but unknown to DB.** File exists but has no row (typical of a prior import that extracted but failed to insert) → the existing file is preserved and the path is passed to `OrphanedAudioScanner.importFiles` so a `Recording` row is created.
3. **Not on disk.** Extracted from the zip and passed to the orphan scanner for a fresh row.

Result: importing the same zip twice produces zero duplicate files on disk and zero duplicate rows in the DB.

### Zip-slip guard

Zip entry names are user-supplied. A malicious zip could contain entries like `../../../etc/passwd`. Every target path is canonicalized and verified to live under `filesDir/recordings/` before any write. Entries that escape the root are skipped silently.

### Import summary

The importer returns an `ImportSummary` (via `OrphanedAudioScanner.ImportSummary`) with per-outcome counts:

- `imported` — recording rows successfully inserted.
- `alreadyKnownPath` — files filtered out at the DB layer because their absolute path was already known.
- `probeFailed` — files that could not be decoded by `MediaMetadataRetriever`. The file is on disk but invisible to the app.
- `insertFailed` — recordings whose `insertRecording` call threw. See `AppLogger` for underlying errors.
- `sessionInsertFailed` — sessions whose `insertSession` call threw. Every segment in that session is also counted under `insertFailed`.

The Settings **Backup and restore** section exposes both flows and displays the summary counts to the user.
