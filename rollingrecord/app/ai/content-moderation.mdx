Custom extraction templates (blueprints) are user-authored system prompts sent verbatim to the AI during extraction, so they pass moderation at SAVE time. `BlueprintModerationService` (`data/moderation/BlueprintModerationService.kt`) is the CLIENT half: a fast local keyword layer that catches obvious cases before spending an Anthropic call. The server's Claude Haiku intent analysis is the authoritative check.

## Layers

| Layer | Where | Mechanism |
| --- | --- | --- |
| Layer 1 (keyword) | Client | `BlueprintModerationService`: exact substring + fuzzy Levenshtein against `JAILBREAK_PATTERNS`, pre-save, no API cost |
| Authoritative | Server | Claude Haiku intent analysis inside the `save_user_blueprint` Edge Function operation |
| Retired | — | prior on-device semantic (poison-vector cosine) layer, removed with the on-device embedding model |

A local pass is not final approval: the server can still reject, surfaced to the client as `BlueprintModerationRejectedException(reason)`. The Haiku intent analysis is NOT part of `BlueprintModerationService` — the client class does keyword matching only.

## The keyword check

`moderate(templateText): Result` returns `Approved` or `Rejected(userMessage)`. It runs entirely on `Dispatchers.Default` (Levenshtein over large text should not block Main) and skips the whole pipeline — approving locally — when `ServerConfig.blueprintModerationEnabled` is false.

`checkKeywords()` has two passes:

1. **Exact** — a fast substring match: if the lowercased text contains any pattern, reject.
2. **Fuzzy** — a word-aligned n-gram sliding window with Levenshtein distance. It splits the input and each pattern into word tokens and compares every consecutive window of the same n-gram size, catching intentional typos (`jailbr3ak`), character swaps (`1gnore`), and near-miss phrases. Max edit distance is `⌊patternLength / 8⌋`, clamped to `[1, 3]` (so `jailbreak` → 1, `ignore previous instructions` → 3). `levenshteinDistance()` uses a two-row rolling array.

On any match it returns the message "This template attempts to override AI safety settings." The `Result` type is a sealed class: `object Approved` and `data class Rejected(userMessage)`.

## `JAILBREAK_PATTERNS`

`JAILBREAK_PATTERNS` (`data/moderation/JailbreakPatterns.kt`) is an `internal val List<String>` of lowercase patterns across 13 categories, matched exactly and fuzzily by `checkKeywords`:

1. Direct instruction override
2. DAN-family and named persona unlocks
3. Role / persona bypass — restriction-removal framing
4. Authority / developer impersonation
5. Continuation / payload injection — prompt delimiters
6. Psychological reframing / hypothetical bypass
7. Capability-unlock claims / state assertions
8. Bypass / circumvention — explicit intent
9. System-prompt extraction / leakage attacks
10. Encoding / obfuscation evasion
11. Output manipulation / format injection
12. Token smuggling / multi-turn setup
13. Grandma / emotional-manipulation exploits

## When it runs, and the config gate

Moderation runs at TEMPLATE/BLUEPRINT SAVE time (before `save_user_blueprint`), not before AI calls in general — KB-chat turns are not client-moderated. It is master-enabled by `ServerConfig.blueprintModerationEnabled`, a `server_config` row whose key is `blueprint_moderation_enabled` (default true). Firebase Remote Config was retired 2026-08-30, and migration `20260830120000_firebase_rc_to_server_config.sql` moved this toggle to `server_config`, renaming the RC key `template_moderation_enabled` to `blueprint_moderation_enabled` — "template" is the feature's retired name, and the client now uses "blueprint" throughout.

`BlueprintValidation` (`agentcore/.../data/repository/BlueprintValidation.kt`) is the shared name / description / prompt validation (`NAME_MAX`, `DESCRIPTION_MIN` / `DESCRIPTION_MAX`) enforced by the editor, the `proposeBlueprint` tool, and the proposal dialog before save.

## From a chat proposal

When the user accepts a `proposeBlueprint` proposal card, `onAcceptBlueprintProposal` (`ui/v2/screens/knowledgebase/V2KnowledgeBaseViewModel.kt`) runs the real `save_user_blueprint` call. A server moderation rejection surfaces as `BlueprintModerationRejectedException.reason` in-card while the proposal stays PENDING so the user can edit and retry.
