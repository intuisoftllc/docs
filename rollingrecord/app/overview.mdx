RollingRecord is a battery-efficient audio recorder that works like a dashcam: alongside a standard **manual** record mode, its **rolling** mode records indefinitely within a user-defined storage limit by pruning the oldest recordings to make room for new ones. On top of capture sit playback, on-device and cloud transcription, an AI knowledge base, encrypted cross-device sync, and a four-tier feature set.

## Where the client lives

The whole Android client is the `app/` part of the monorepo, split into four Gradle modules:

| Module | What it is |
| --- | --- |
| `app/app` | The Android application — single-Activity Jetpack Compose (the V2 UI is the active surface), min SDK 26 / target SDK 36. |
| `app/crypto` | Pure Kotlin/JVM encryption primitives, shared with the backend smoke tests by source inclusion for crypto parity. |
| `app/agentcore` | The pure-JVM KB-chat agent loop (`AgentLoop`, wire models, tool contract) shared by the app and the eval runner. |
| `app/agentrunner` | A pure-JVM CLI that drives the real agent loop for the eval harness. |

Inside `app/app`, code is organized by concern: `service` (foreground recording), `audio` (capture + encoding), `data` (Room, repositories, session), `ui/v2` (Compose screens, navigation, theme, gating), `worker` (WorkManager jobs), `handlers`, `tiles` (Quick Settings), `notification`, `receiver`, `config`, and `di` (Koin).

## The four tiers

The feature set is defined in `UserTier.kt` (`data/models/UserTier.kt`) as four tiers, each a strict superset of the one below:

| Tier | Adds |
| --- | --- |
| **Free** | Manual + rolling recording, playback, local transcription — a finished product, not a crippled one. |
| **Pro** | Scheduled recordings, trim, and the other paid on-device features. |
| **Pro+Cloud** | Encrypted cross-device sync and cloud audio backup. |
| **Cloud+AI** | Cloud transcription, the AI knowledge base, extraction, and synthesis. |

Tier is resolved from RevenueCat entitlements and enforced both client-side (feature gating) and server-side (the Edge Function gate chain). See [Tiers](/rollingrecord/app/monetization/tiers) and [Feature gating](/rollingrecord/app/monetization/feature-gating).

## Cross-cutting foundations

- **Single-Activity Compose.** One Activity hosts the V2 Compose UI; navigation, theme, and gating live under `ui/v2`. See [UI & navigation](/rollingrecord/app/architecture/ui-and-navigation).
- **Per-user session isolation.** Koin app-level singles plus a `UserSessionScope` that is torn down and rebuilt on every sign-in / sign-out, so no account's state leaks into the next. See [User-session scope](/rollingrecord/app/architecture/user-session-scope).
- **Encrypted at rest.** Audio and the Room database are sealed with per-recording data keys and a database key, wrapped by envelope encryption. See [Envelope encryption](/rollingrecord/app/security/envelope-crypto).
- **The agent loop is shared code.** The KB-chat loop runs the same `app/agentcore` code the eval harness drives, so what ships is what's tested. See [Agent loop](/rollingrecord/app/ai/agent-loop).
