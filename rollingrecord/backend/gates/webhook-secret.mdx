---

`functions/_shared/gates/webhook-secret.ts` authenticates callers that have no Play Integrity token and no user session — RevenueCat and AssemblyAI webhooks, `pg_cron` sweepers, and the `extract-runner` tick. Each such function pairs `AuthMode.WebhookSecret` with its own dedicated secret and opts out of App Check and App Version, since those callers never send device headers.

## The gate

`runWebhookSecretGate(req, secretEnvVar = "REVENUECAT_WEBHOOK_SECRET")` reads the named env var and compares it against the `Authorization: Bearer <secret>` header, returning `null` on a match or `401 invalid_signature` otherwise. The low-level primitive `verifyWebhookSecret(authHeader, secretEnvVar)` (exported for smoke tests) returns `false` when the secret is unset (logged), the header is missing, or the header isn't `Bearer <secret>`, and otherwise does a constant-time compare.

`timingSafeEqual(a, b)` iterates over the max of both byte lengths and XOR-accumulates the difference, so an attacker measuring response latency cannot recover the secret character by character — every call takes the same time regardless of how many leading bytes matched.

## No user identity

In `runGates`, `AuthMode.WebhookSecret` produces a `WebhookSuccessCtx` of `{ response: null, auth: AuthMode.WebhookSecret }` — no `authUserId`, no `email`. Downstream handlers cannot read user fields; attempting to is a compile error.

Optional `rateLimit` sugar is supported but rarely used. Because there is no user identity, the subject key is the literal string `__webhook__:<bucket>`, so all webhook callers of that bucket share a single counter, and there is no dev bypass — there is no user to key on or bypass for.

## Dedicated per-function secrets

Each server-to-server function uses its own secret env var rather than the service-role key (least privilege). All of them also opt out of App Check and App Version.

| Function | `secretEnvVar` | Caller | Also opts out |
| --- | --- | --- | --- |
| `revenuecat-webhook` | `REVENUECAT_WEBHOOK_SECRET` (default) | RevenueCat webhook infra | `skipAppCheck` + `skipAppVersion` |
| `assemblyai-webhook` | `ASSEMBLYAI_WEBHOOK_SECRET` | AssemblyAI transcription webhook | `skipAppCheck` + `skipAppVersion` |
| `storage-janitor` | `STORAGE_JANITOR_SECRET` | `pg_cron` `net.http_post` / another Edge Function | `skipAppCheck` + `skipAppVersion` |
| `storage-orphan-lister` | `STORAGE_JANITOR_SECRET` | `pg_cron` `net.http_post` | `skipAppCheck` + `skipAppVersion` |
| `extract-runner` | `EXTRACT_RUNNER_SECRET` | `pg_cron` self-call + `extract-submit` inline kick | `skipAppCheck` + `skipAppVersion` |
| `analytics` | `ANALYTICS_INGEST_SECRET` | eval harness machine (server-to-server) | `skipAppCheck` + `skipAppVersion` |

The failure code is always `invalid_signature` (`401`), defined in `functions/_shared/errors.ts`.

## The clerk-webhook exception

`clerk-webhook` does **not** use this gate. It runs `AuthMode.None` and verifies the Svix signature itself inside its handler body — it is not a `REVENUECAT` / `STORAGE` / `EXTRACT`-style shared-secret caller, even though it is server-to-server and opts out of App Check and App Version the same way.
