---

Server logic is tested in two disjoint layers. Deno unit tests under `supabase/tests/` cover deterministic pure logic in milliseconds; the standalone `smoketest/` Gradle build drives behavior through the real Edge Function HTTP surface and its full gate chain. A `CLAUDE.md` HARD RULE decides which layer a given piece of new code belongs to.

## The two layers

| Layer | Location / runner | Scope | Uses |
|---|---|---|---|
| Deno pure-logic unit tests | `supabase/tests/` · `deno task test` (`deno test --no-check`) | deterministic logic **only** — no network, DB, env, filesystem, or gate chain | cost math, parsers, validators, formatters, prompt assembly, registries, sync / extraction / crypto transforms |
| Gate-chain smoke tests | `smoketest/` (standalone Gradle) · `cd smoketest && ./gradlew test` | the real Edge Function HTTP path — full gate chain, Clerk auth, App Check, validation, RPC | service-role key for **preconditioning + assertion reads only**, never to execute the op under test |

The two are complementary, not redundant: the unit layer pins logic without an HTTP round-trip, and the smoke layer proves the whole pipeline admits and rejects requests correctly.

## Layer 1 — Deno unit tests

`supabase/tests/` mirrors the source tree: `functions/_shared/ai/pricing.ts` is tested by `tests/_shared/ai/pricing_test.ts`. Tests use `Deno.test` blocks and `@std/assert`, imported back into `functions/` by relative path. The `test` task is defined in `tests/deno.json`:

```bash
cd supabase/tests
deno task test        # → deno test --no-check
```

<Note>
The task passes `--no-check` deliberately. Some test files transitively import source modules (`sync-push` / `sync-pull`, `usage-counters`) that carry pre-existing TypeScript errors unrelated to the tests — a dual `@supabase/supabase-js` version plus a few stale casts. The tests verify runtime behavior; cleaning up those source type errors is tracked separately.
</Note>

Representative coverage across the mirrored tree:

| Area | Test files (`tests/`) |
|---|---|
| Error registry | `_shared/errors_test.ts` — no duplicate codes, size parity, snake_case, 4xx/5xx status, non-empty descriptions |
| Cost math / AI failover | `_shared/ai/pricing_test.ts`, `_shared/transcribe/pricing_test.ts`, `_shared/ai/providers/failover_test.ts` — `shouldFailOver` classification (a `401` auth error must fail over to the next provider; request-shaped `400` / `404` / `413` must not) |
| Sync transforms | `_shared/sync/*_test.ts`, `sync-pull/*`, `sync-push/*` — cursor encode/decode, entity/group mapping, request/response shaping |
| Extraction logic | `_shared/extraction/*_test.ts` — accumulator, billing, context-budget, job-status, messages, runner-classify, runner-plan |
| Text / DB-write sanitization | `_shared/text/db_text_test.ts` — `sanitizeDbText` strips NUL / C0 controls at the TEXT-column write boundary (an unstripped `U+0000` fails the whole INSERT); `_shared/bugreport/sanitize_test.ts` — bug-report description / area normalize + client-metadata sanitize |
| Health probes | `_shared/gates/health_test.ts` — `shouldRunProbe` gate short-circuit + `buildHealthResponse` shaping (`200` ok / `503` degraded, no labels leaked); `_shared/db/health-checks_test.ts` — the pure `db*HealthResult` interpreters (the `requires both / all three` rule) |
| Crypto / OTP / email / billing / db | `_shared/crypto/*`, `_shared/otp/*`, `_shared/email/otp-email_test.ts`, `_shared/billing/entitlements_test.ts`, `_shared/billing/revenuecat_test.ts` (`decideCacheUse` entitlement cache-bypass throttle), `_shared/db/*_test.ts` (credit-ceiling, metered-ops, storage-quota, usage-caps, `admin_credit_budget_test.ts` operator per-rolling-30-day grant ceiling) |
| Per-function pure logic | `ai-engine/*`, `support-ops/operations/*`, `notifications/cloud-wipe-warning_test.ts`, `indexing/bundle-requests_test.ts`, `storage-janitor/buckets_test.ts`, `storage-orphan-lister/predicates_test.ts`, `set-user-pin/pin-settings_test.ts`, `analytics/validation_test.ts` |

## Layer 2 — Gate-chain smoke tests

`smoketest/` is a **standalone** Gradle build — not a module of the app build. Run it from its own directory:

```bash
cd smoketest && ./gradlew test
```

The suite has 60-plus `*SmokeTest.kt` classes (`AiEngine*`, `Sync*`, `Extract*`, `SupportOps*`, `Bundle*`, `DeleteUser*`, `RateLimit*`, `CloudResetSmokeTest`, `Search`, `Indexing`, tier-gate enforcement, and more). Each drives the operation under test through the real Edge Function HTTP surface so the whole admission chain — App Check, Clerk JWT, entitlement, rate limit, structural validation, RPC — executes for real. `CloudResetSmokeTest` (added this commit) is a good example: it drives the new `cloud_reset` sync-pull status — the signal that stops a resubscribing device from deleting content the user never deleted — with a real `POST` to `sync-pull` through the full gate chain, and reads back internal state with the service-role client only to assert.

The service-role key exists in the harness for **preconditioning** state (seeding `user_storage_usage` near a cap, `usage` rows near a limit, specific ciphertext for a trigger) and for **assertion reads** against internal tables the response body doesn't expose. It must never execute the operation under test — that would bypass every enforcement layer and test only the SQL layer. The `c_recordings` crypto-integrity rule applies here too: smoke tests never raw-`DELETE` `c_recordings` or null its crypto columns for real-user-flow rows; teardown routes through the matching Edge Function, and only synthetic throwaway rows may be REST-deleted.

<Note>
The harness signs in with `+clerk_test` fixture accounts (e.g. `canary_a+clerk_test@gmail.com`), which receive the fixed OTP `424242` when the dev-only `CLERK_TEST_EMAILS_ENABLED` toggle is set — see [Environment Variables & Secrets](/rollingrecord/backend/operations/env-and-secrets). This is a runtime toggle plus a fixture email convention, not a schema change; there is no migration behind it.
</Note>

## Classifying new server code

The HARD RULE **Deno Unit Tests for New Server Logic** requires you to classify every new or changed function in `functions/` before considering the work done:

| Kind | Where it's tested |
|---|---|
| Pure (deterministic, no I/O) | **must** add / update a `*_test.ts` under `supabase/tests/`, mirroring the source path |
| Impure (DB / provider HTTP / env / gate chain / the HTTP handler itself) | covered by `smoketest/` per the gate-chain rule — not a Deno unit test |
| Mixed | export the isolable pure function and unit-test that; leave the rest to `smoketest/` |
| Unsure | default to writing the Deno unit test — a pure function with a test is never wrong |

A pure function shipped without a test erodes the fast-feedback coverage one commit at a time, which is exactly what `supabase/tests/` exists to prevent.
