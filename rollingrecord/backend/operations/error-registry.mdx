`supabase/functions/_shared/errors.ts` is the single source of truth for every `error` string any Edge Function returns to the client. No function may inline an error string — the constant is the contract, enforced by a `CLAUDE.md` HARD RULE. A Kotlin enum mirrors the registry one-to-one, a drift test holds them in parity, and a Python script regenerates a human-readable table on demand.

## The registry: three category objects

Codes are built by a compact `def(code, category, httpStatus, description)` factory into three exported objects, then spread into one combined `AppError`. The `category` field — not which object a code sits in — is what drives client presentation.

| Object (`_shared/errors.ts`) | Category meaning | Client treatment |
|---|---|---|
| `USER_ERRORS` | `user` | friendly UI message, maps to a typed `AiEngineResult` variant |
| `INFRA_ERRORS` | `infra` | generic "service unavailable, retry" — the client backs off |
| `DEV_ERRORS` | `developer` | never shown; logged to Crashlytics as "something went wrong" |

Representative codes per category:

| category | Examples |
|---|---|
| `user` | `cap_reached`, `subscription_required`, `moderation_failed`, `step_up_required`, `backup_quota_exceeded`, `semantic_search_disabled`, `admin_grant_budget_exceeded` |
| `infra` | `all_providers_failed`, `rate_limited`, `provider_rate_limited`, `database_error`, `fk_violation`, `embedding_failed` |
| `developer` | `invalid_jwt`, `handler_threw`, `missing_operation`, `model_not_allowed`, `extraction_undecryptable`, `admin_hmac_mismatch`, `bug_report_insert_failed` |

<Note>
Object and category are not identical. `batch_too_large`, `size_mismatch`, and `recovery_code_invalid_operation` are physically defined inside `USER_ERRORS` but carry category `"developer"`. Both the Kotlin mirror and the doc generator bucket by the `category` field, so these three appear under Developer errors — don't assume the enclosing object equals the category.
</Note>

## Combined surface and lookup

Three helpers close the registry:

| Symbol (`_shared/errors.ts`) | Role |
|---|---|
| `AppError` | `{ ...USER_ERRORS, ...INFRA_ERRORS, ...DEV_ERRORS }`; call sites reference `AppError.X.code` / `AppError.X.httpStatus` |
| `ALL_ERROR_CODES` | `ReadonlySet<string>` of every code, for smoke-test drift checks; its size must equal `Object.keys(AppError).length` |
| `errorCategory(code)` | resolves a code back to its `ErrorCategory`, or `null` for an unknown code |

Because the three objects are spread into one, a duplicate `code` string across groups would silently shadow. `tests/_shared/errors_test.ts` pins against exactly that: no duplicate codes, `ALL_ERROR_CODES.size == AppError` key count, snake_case codes, `httpStatus` in the 4xx/5xx range, non-empty descriptions, and valid categories.

## The Kotlin mirror

The client mirrors the registry as `enum class AiEngineErrorCode(val code: String, val category: Category)` with a nested `enum class Category { USER, DEVELOPER, INFRA }` and a `fromCode()` lookup. The name is historical — despite the `AiEngine` prefix it covers every Edge Function's codes, not just `ai-engine`.

<Warning>
The Kotlin mirror's real path is `app/agentcore/src/main/kotlin/com/intuisoftllc/rollingrecord/data/remote/aiengine/AiEngineErrorCode.kt` — inside the pure-JVM `agentcore` module. The `errors.ts` header comment cites a wildcard `app/.../data/remote/aiengine/AiEngineErrorCode.kt` path; only the `CLAUDE.md` rule cites the outdated `app/app/.../AiEngineErrorCode.kt` module path. Use the `agentcore` path.
</Warning>

`AiEngineErrorCodeDriftTest` parses the TypeScript registry at test runtime and asserts exact **bidirectional** parity between the enum and `errors.ts`. Adding a code on only one side fails the build — the fix is to add it on both, never to `@Ignore` the test. This commit added four codes on **both** sides in the same change, preserving that parity: `admin_grant_budget_exceeded` (`USER_ERRORS` / `Category.USER`, HTTP 403 — the operator's own per-rolling-30-day grant ceiling, distinct from `credit_ceiling_exceeded` which bounds what a customer may hold) and the bug-report trio `bug_report_empty_description` (400), `bug_report_description_too_long` (400), and `bug_report_insert_failed` (500), all in `DEV_ERRORS` / `Category.DEVELOPER`.

## Registry → mirror → docs pipeline

| Artifact | File | Role |
|---|---|---|
| TypeScript registry (source of truth) | `functions/_shared/errors.ts` | `USER` / `INFRA` / `DEV_ERRORS` + `AppError` + `ALL_ERROR_CODES` + `errorCategory` |
| Kotlin mirror | `app/agentcore/.../aiengine/AiEngineErrorCode.kt` | 1:1 enum, category-tagged, `fromCode()` |
| Drift guard | `AiEngineErrorCodeDriftTest` | parses the TS at runtime, asserts bidirectional parity |
| Unit tests | `tests/_shared/errors_test.ts` | no-duplicates + well-formedness |
| Generated doc | `docs/error-codes.md` (via `scripts/gen_error_docs.py`) | human-readable, regenerated on demand |

`supabase/scripts/gen_error_docs.py` reads `errors.ts`, matches each `CONST: def("code", "category", STATUS, "desc")` with a `DOTALL` regex (`ENTRY_RE`) that also collapses TypeScript `"a" + "b"` string concatenation, and writes `docs/error-codes.md` with a per-category count summary plus one table per category sorted by code. Run it from the repo root:

```bash
python supabase/scripts/gen_error_docs.py
```

<Warning>
`docs/error-codes.md` is a **point-in-time snapshot regenerated on demand, not in CI** — so it can drift between regenerations. This commit regenerated it, closing most of the gap: the whole `bundle_*` purchase family (`bundle_already_credited`, `bundle_already_refunded`, `bundle_no_grant_found`, `bundle_rc_transaction_*`, `bundle_sku_unknown`) is gone from the snapshot as it already was from `errors.ts` and the Kotlin mirror, and previously-lagging codes (`password_rejected`, `super_admin_protected`, the `user_delete_*` family) that already existed in `errors.ts` were finally folded in. But the snapshot is **not** fully in sync: it reads **154** total (User-facing 52 / Infrastructure 11 / Developer 91), while `errors.ts` actually defines **156** (User-facing **54** / Infrastructure 11 / Developer 91). The two missing codes are the user-category `amount_not_integer` and `storage_cap_would_be_exceeded` — both are silently dropped by `gen_error_docs.py`, whose `ENTRY_RE` description group (`"[^"]*(?:"\s*\+\s*"[^"]*)*"`) cannot parse a description containing an escaped double-quote (`\"…\"`), which both of those definitions have. So the snapshot still trails the registry by 2 user codes until that regex is fixed. Treat `errors.ts` as authoritative and regenerate the markdown after any code change, since nothing enforces it between runs.
</Warning>

## The single exception to "no inline literals"

`functions/_shared/gates/jwt.ts` returns a `VerifyBearerResult` discriminated union with narrow string-literal `error` types (`"missing_bearer_token"`, `"invalid_jwt"`) so consumers can exhaustively pattern-match. Those literals must match the registry codes exactly and are renamed in the same commit as any registry rename. Any new helper needing this pattern gets the same treatment: literal in the type, matching registry entry, paired updates.
